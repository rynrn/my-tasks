# /next-task — קידום סטטוס משימה

מטרה: לאפשר למשתמש לקדם בקלות משימה במחזור הסטטוסים, ולהשאיר את `DASHBOARD.md` מסונכרן.

## מודל הסטטוסים (checkbox markdown)

| תצוגה   | משמעות           | מחזור הקידום                     |
|---------|------------------|----------------------------------|
| `- [ ]` | עדיין לא התחיל   | → `- [~]` (בתהליך)              |
| `- [~]` | בתהליך           | → `- [x]` (הסתיים)              |
| `- [x]` | הסתיים           | (סופי — שאל אם להחזיר ל-`[ ]`)  |

## תהליך עבודה

0. **pull לפני שמתחילים** — הרפו משותף בין כמה מחשבים, עובדים על `main` בלבד:
   ```bash
   git pull --rebase origin main
   ```
   אם ה-pull נכשל — עצור ודווח למשתמש, אל תפתור קונפליקטים לבד.

1. **זיהוי המשימה** — אם המשתמש לא ציין משימה ספציפית:
   - הרץ סריקה על כל קבצי `*/tasks.md` ובחר עד 10 משימות פתוחות (`[ ]` או `[~]`) עם עדיפות `[HIGH]` קודם, אחר כך `[MED]`.
   - הצג רשימה ממוספרת והמתן לבחירה (אפשר להשתמש ב-AskUserQuestion).
2. **קביעת היעד החדש** — קדם לפי הטבלה למעלה. אם המשתמש ביקש סטטוס ספציפי ("סמן כבתהליך", "סגור את זה"), כבד את הבקשה.
3. **עדכון הקובץ** — השתמש ב-Edit כדי להחליף את התו בתוך הסוגריים בלבד (` `, `~`, או `x`). שמור על שאר השורה (תיוג רמת דחיפות + תיאור).
4. **סנכרון DASHBOARD.md**:
   - אם המשימה היא `[HIGH]` — עדכן את אותה שורה גם ב-`DASHBOARD.md` תחת הקטגוריה והסקשן המתאימים.
   - אם המשימה אינה `[HIGH]` — לא צריך לגעת ב-DASHBOARD.
5. **דווח למשתמש בקצרה** — שורה אחת: איזו משימה עודכנה, מה הסטטוס החדש, ובאיזה קובץ.

6. **commit + push** — אחרי שהקבצים נשמרו:
   ```bash
   git add -A
   git commit -m "update task: <תיאור קצר + סטטוס חדש>"
   git push origin main
   ```
   הודעת commit באנגלית קצרה (למשל `update task: tax refund → done`). בלי `Co-Authored-By`. אם ה-push נכשל — דווח, אל תשתמש ב-`--force`.

## כללים חשובים

- אל תשנה את התיוג (`[HIGH]` / `[MED]` / `[LOW]`) ואל תשנה את התיאור.
- אל תזיז משימות בין סקשנים — שמור על המבנה (שוטף / דחוף / פרויקטים).
- אם משימה הסתיימה (`[x]`) ויש לה גרסה ב-DASHBOARD — עדכן גם שם, אל תמחק.
- אם המשתמש מבקש לבטל סימון (`[x]` → `[ ]`) — אשר לפני הביצוע.
- כל הפעולות פנימיות לרפו `my-tasks` בלבד.
