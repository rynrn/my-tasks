# /add-task — הוספת משימה חכמה

מטרה: לקלוט הודעה חופשית בעברית, להבין לאן המשימה שייכת ובאיזה סקשן, ולהוסיף אותה לקובץ הנכון. לבקש הבהרה רק כשבאמת חסר מידע קריטי.

## 1. זיהוי קטגוריה (תיקייה)

מפה את המשימה לאחת מ-6 הקטגוריות לפי מילות מפתח. **התאמה לפי הקשר, לא חיפוש מילולי קשיח.**

| תיקייה                  | מילות מפתח / רמזים                                                                                                |
|-------------------------|-------------------------------------------------------------------------------------------------------------------|
| `home/`                 | בית, בייתי, דירה שלנו, דירת המגורים, מטבח שלנו, מזגן, אינסטלציה (בבית), שיפוץ (בבית), גינה, מחסן                  |
| `finance/`              | פיננסי, כסף, אשראי, כרטיס, בנק, מס, החזר, השקעה, פנסיה, קרן, חיסכון, תקציב, ביטוח, הוראת קבע, תשלום (לא לקבלן)    |
| `investment-apartment/` | דירה בקצרין, קצרין, דירה להשקעה, דירת השקעה, הקבלן, מתן (יועץ משכנתא), פקודת תשלום, ערבות בנקאית, משכנתא, השוכר   |
| `hosting-unit/`         | יחידה, יחידת אירוח, אירוח, אורחים, Airbnb, Booking, צ'ק-אין, מנקה, מלאי סדינים, רישיון עסק                       |
| `family/`               | משפחה, ילדים, הבן, הבת, ההורים, סבתא/סבא, בית ספר, חוגים, ילד, רופא ילדים                                          |
| `couple/`               | זוגי, זוגיות, ריקי (בת הזוג), דייט, יום נישואין, סוף שבוע רומנטי, יועץ זוגי, חופשה זוגית, חג / אירוע משותף         |

**כללי הכרעה כשיש חפיפה:**
- "ביטוח בריאות" → `finance` (תשלום), אלא אם מדובר במצב רפואי קונקרטי של בן משפחה.
- "תשלום לקבלן / משכנתא" → `investment-apartment` (לא `finance`).
- "טיול / חופשה" — אם יש זכר לילדים → `family`; אם רק עם בן/בת הזוג → `couple`.
- אם באמת לא ברור — **שאל** את המשתמש לפני שמירה (אל תנחש).

## 2. זיהוי סוג המשימה (סקשן)

| סקשן בקובץ                 | מתי                                                                          |
|----------------------------|------------------------------------------------------------------------------|
| `## 🔁 שוטף (חוזר)`        | המשתמש אמר "כל חודש", "כל שבוע", "פעם ב...", "אחת ל...", "חוזר", "שוטף"      |
| `## ⚡ דחוף / חד פעמי`     | פעולה נקודתית שצריך לסגור פעם אחת. ברירת המחדל לרוב המשימות.                  |
| `## 📌 פרויקטים (ארוך טווח)` | המשתמש אמר "פרויקט", "ארוך טווח", "בעוד שנה", "מתי שיהיה זמן", או יוזמה רב-שלבית גדולה |

**אם לא ברור — שאל:** "זו משימה חד פעמית, חוזרת, או פרויקט ארוך טווח?"

## 3. זיהוי רמת דחיפות

| תגית     | מתי                                                                                |
|----------|------------------------------------------------------------------------------------|
| `[HIGH]` | המשתמש אמר "דחוף", "חשוב", "מיידי", "בהול", או יש דדליין קרוב / סיכון בטיחותי     |
| `[MED]`  | חשוב אבל לא בוער. ברירת מחדל סבירה כשלא ברור.                                       |
| `[LOW]`  | "כשיהיה זמן", "נחמד שיקרה", "אי פעם"                                              |

**אם לא ברור — שאל:** "מה הדחיפות? HIGH (דחוף) / MED (בינוני) / LOW (כשיהיה זמן)?"

## 4. תהליך עבודה

1. **קרא את ההודעה** וזהה: קטגוריה, סוג (סקשן), דחיפות.
2. **אם חסר משהו** מבין השלושה ולא ניתן להסיק בביטחון — שאל את המשתמש (העדף שאלה אחת מאוחדת אם חסרים שניים).
3. **אם הקטגוריה לא ברורה ב-100%** — אשר עם המשתמש לפני שמירה ("הבנתי שזו משימה ליחידת האירוח, נכון?").
4. **כתוב את השורה** בפורמט הסטנדרטי: `- [ ] [LEVEL] תיאור המשימה`.
5. **הוסף לקובץ** באמצעות Edit — בסוף הסקשן הנכון, לפני הסקשן הבא (או בסוף הקובץ אם זה הסקשן האחרון). שמור על שורה ריקה בין הכותרת לפריטים.
6. **אם המשימה היא `[HIGH]`** — הוסף את אותה שורה גם ל-`DASHBOARD.md` תחת הקטגוריה והסקשן המתאימים.
7. **דווח בקצרה** — שורה אחת: "✓ הוספתי ל-`<קטגוריה>/tasks.md` תחת <סקשן>: <תיאור>."

## 5. כללים חשובים

- אל תיצור קטגוריות חדשות. רק 6 הקיימות.
- אל תשנה / תמחק משימות קיימות — רק תוספת.
- אל תוסיף משימות מומצאות שלא ביקשו ממך.
- אם המשתמש מתאר כמה משימות בהודעה אחת — עבד אותן אחת אחרי השנייה (אפשר לבקש תשובה אחת על כולן יחד אם חסר מידע דומה).
- שאלות הבהרה — בעברית, קצרות, ענייניות.

## 6. סנכרון Git (חובה לפני ואחרי עריכה)

הרפו משותף בין כמה מחשבים — עובדים על `main` בלבד.

**לפני שמתחילים לערוך קבצים:**
```bash
git pull --rebase origin main
```
אם ה-pull נכשל (קונפליקט / שינויים מקומיים לא מקומיטים) — **עצור ודווח למשתמש**, אל תנסה לפתור לבד.

**אחרי שכל המשימות נוספו והקבצים נשמרו (כולל DASHBOARD אם רלוונטי):**
```bash
git add -A
git commit -m "add task: <תיאור קצר של המשימה/ות שנוספו>"
git push origin main
```

הודעת ה-commit באנגלית, קצרה, מתחילה ב-`add task:`. אם הוספת כמה משימות בקריאה אחת — שורה אחת מסכמת ("add task: 3 hosting-unit tasks"). אל תוסיף `Co-Authored-By` או חתימות נוספות.

אם ה-push נכשל — דווח, אל תנסה `--force`.

## 7. דוגמאות

**משתמש:** "תוסיף משימה לדירה בקצרין — לבדוק את הריצוף בסלון, זה דחוף"
**אתה:** מזהה `investment-apartment` + `[HIGH]` + חד פעמי. כותב לקובץ ולדשבורד. מדווח: "✓ הוספתי ל-`investment-apartment/tasks.md` תחת ⚡ דחוף: לבדוק את הריצוף בסלון."

**משתמש:** "תזכיר לי לקנות מתנה לריקי ליום נישואין"
**אתה:** מזהה `couple` + חד פעמי. דחיפות לא ברורה — שואל: "מה הדחיפות? HIGH / MED / LOW?"

**משתמש:** "יש לי משימה ליחידה: לנקות מסנני מזגן כל חודשיים"
**אתה:** מזהה `hosting-unit` + שוטף (כל חודשיים) + דחיפות לא צוינה — שואל רק על דחיפות.

**משתמש:** "תוסיף משימה: לבדוק ביטוחים"
**אתה:** הקטגוריה לא ברורה (finance? family?). שואל: "לאיזו קטגוריה — `finance` או משהו אחר? וגם, חד פעמי או חוזר, ובאיזו דחיפות?"
